# 信号争夺 · 开发日志

> 更新时间：2026-08-06
> 低配电脑可运行的单机人机射击肉鸽小游戏（无需安装依赖）

---

## 一、项目概览

- **运行**：`node server.js` → 浏览器打开 `http://localhost:3000`
- **架构**：Node 服务端权威模拟 + 浏览器 Canvas 渲染 + 自实现 WebSocket 实时通信
- **节奏**：服务端 tick 60fps；客户端渲染走 `requestAnimationFrame`
- **设计初衷**（Codex 早期对话）："电脑红方 + 手机蓝方"双人对抗。因实际只有一台电脑，最终以**单人 vs AI** 形式落地；手机/双人功能**未真正实现**（本日志中多次问题由此埋下）

### 代码结构

| 文件 | 职责 |
|---|---|
| `server.js` | 游戏规则、AI、WebSocket 服务端 |
| `app.js` | 输入、渲染、HUD、升级界面 |
| `index.html` / `style.css` | 页面与样式 |
| `docs/开发日志.md` | 本日志 |

## 二、迭代记录（按 git 提交）

### 2.1 初始提交（`7b0fa33`）

- 单人 vs AI：90 秒内抢能量核心，每 3 枚触发三选一强化
- 已有核心玩法：波次、核心、强化、击败 AI
- 已知隐患：单玩家实体 + `game.controller` 由"最后 join 者"担任

### 2.2 第 1 轮 · 输入处理优化

**目标**：解决按键卡住/失灵。

- 键位改用物理键码 `e.code`（不受键盘布局影响），`ShiftLeft/ShiftRight` 均支持冲刺
- 屏蔽中文输入法（IME）合成事件，避免 keyup 被吞导致按键卡住
- 失焦、切标签页、IME 启动时自动清空按键状态
- 按住键自动重复只处理一次

### 2.3 第 2 轮 · 移动逻辑修复（`bb6919b` 的前半部分）

**目标**：修复"无法移动"的隐性逻辑问题。

- 死亡重生：原逻辑死后原地冻结 2.6s 再瞬移回地图中心，且 bot 接触伤害不检查 `respawn`，被围住会**反复触发死亡、永久卡死**
  - 改为：原地重生 + 1.5 秒无敌、不再瞬移；接触伤害与子弹都尊重 `respawn`/`invuln`
- 修复竖直瞄准 bug：服务端 `Number(aimX) || 1` 会把合法的 `0` 改写为 `1`，导致无法垂直瞄准
- 服务端 tick 由 30fps 提到 60fps（AI 开火概率按 `dt` 重平衡以保持原射击频率）

### 2.4 第 3 轮 · 客户端预测与平滑渲染（`bb6919b`）

**目标**：消除"移动不跟手 / 顿挫"。

- 客户端玩家位置预测：用当前输入即时计算速度，从服务端权威位置外推，按键响应接近零延迟；平滑追赶避免瞬移/回弹，静止零漂移
- 服务端下发玩家当前 `speed`（含升级后），客户端据此精确预测
- bot 平滑渲染（跨 tick 收敛）
- 验证数据（Node 模拟 60fps）：静止收敛 0.00px、停止响应 4 帧、反向 2 帧、预测误差封顶 9.7px

### 2.5 第 4 轮 · 控制器冲突修复（`c009bc7`）

**目标**：修复"只能小范围移动 + 子弹发射不了"。

- **根因**：游戏本意双人，但实现只有单一 `game.player`。任何客户端 join 或发输入都会成为 `game.controller`。手机（或残留标签页）一连上就抢走控制权 → 电脑 WASD/空格输入被忽略 → 角色停在原地（小范围抖动为客户端预测在冻结位置附近的抖动），子弹发不出
- 改动：只有发出**非零移动/射击输入**的客户端才成为控制器；观战客户端不抢占

### 2.6 第 5 轮 · 移除观战逻辑（`274e553`）

**目标**：修复"我电脑进去也显示观战"。

- **根因**：上一轮把控制器改为"按下非零键才算"，打开页面未按键时 `controller` 为空，被误判为观战
- 改动：打开页面（join）即成为控制端；移除 `you`/观战 UI；README 改为单人玩法提示

### 2.7 第 6 轮 · 输入法 keyCode 229 修复（`813bbc6`）

**目标**：修复"彻底无法移动和攻击"。

- **根因**：Windows + Chrome + 中文输入法环境下，W/A/S/D 的 `keydown` 会上报 `keyCode=229`（VK_PROCESS），`e.key` 可能为 `"Process"`。此前用 `keyCode===229` 屏蔽输入法按键，把正常 WASD 也误杀
- 改动：改用物理键 `e.code` + 仅 `e.isComposing` 屏蔽真正的输入法合成，另加 `e.key` 兜底映射
- 验证：7 种按键事件形态全部映射正确（含"输入法活动但 `e.key=Process`"场景）

### 2.8 第 7 轮 · 诊断进行中（`b1edaa5` → `207e662`）

**目标**：定位"玩家仍动不了 + 再来一局无反应"。

- 已确认：浏览器跑最新代码、`ws=1` 连接正常、`you=true` 是控制端、客户端确实发出 `输入=(1,0)`
- 已确认：服务器端能正常响应输入（工具客户端实测移动 291px、射击出弹）
- 已加诊断：页面左上角临时调试面板（版本号 / ws / you / 输入 / 收到 / 应用 / 玩家位置）+ 服务器 `[net]` 日志

### 2.9 第 8 轮 · 根因闭环（`20d4554`）

**目标**：自主闭环"玩家动不了 + 再来一局无反应"（不再依赖用户手动测数据）。

- 搭建**无头浏览器测试**（puppeteer-core + 系统 Chrome 无头模式），真实复现：keydown 正常、客户端发 x=1，但服务器收到 x=0
- 加服务器逐帧日志确认：收到的 input 全是默认零输入，`start` 正常而 `input` 丢失
- **定位根因**：WebSocket 帧解析器不支持 16 位扩展长度帧（载荷 ≥126 字节）；浏览器输入消息带长小数 aimX/aimY 超长触发扩展帧，解析错位 → 帧流脱同步 → input 全丢
- **修复**：`size===126` 时用 `readUInt16BE` 读取真实 16 位长度
- 无头浏览器实测：按住 D 移动 214px、空格出弹、无 JS 错误
- 清理全部诊断日志/面板，保留 `window.__state` 便于后续调试

### 2.10 功能：属性面板与 XP 系统（`18b2dae`）

- **属性面板**：左下角实时显示 等级/生命/伤害/射速/弹速/移速/拾取/减伤，达到上限标"满"
- **XP 进度条**：右上角显示当前等级所需经验进度
- **经验曲线**：`xpToNext(level) = 3 + ⌊(level-1)×1.5⌋`，升级所需经验随等级递增（3、4、6、7、9、10、12…）
- **`addXp` 统一处理**经验累加与升级触发，支持一次多级
- **属性上限**：射速≥0.35、移速≤410、伤害≤80、生命≤400、拾取≤200、弹速≤1500、减伤≤48%（留足余地，避免过早封顶）
- 已满级的强化不再出现在三选一池中

## 四、核心问题：根因与修复（已闭环）

**症状**：按住 D 时面板 `输入=(1,0)` 但 `应用=(0,0)`，玩家不动；点"再来一局"无反应。

**根因**：服务器自实现的 WebSocket 帧解析器**只支持 125 字节以内的短帧**。浏览器发送的输入消息带上鼠标算出的长小数（`aimX:0.7071067811865476`），JSON 超过 125 字节，浏览器按 RFC 6455 改用**"16 位长度"扩展帧**发送；而解析器用 `byte1 & 127` 当长度、**忽略了真正的 16 位长度字段** → 解析错位、帧流脱同步，**后续所有 input 帧全部丢失**。`start` 等短消息正常，所以游戏能开始但动不了/射不了。

**为何此前测不出来**：手工测试客户端一直发 `aimX:1`（短消息 <125 字节）没触发；真实浏览器发长小数才触发。

**修复**：`size===126` 时用 `readUInt16BE(2)` 读取真实长度并正确跳过头部。

**验证**：无头浏览器（Chrome）实测——按住 D 玩家移动 214px、空格出弹、无 JS 错误。

## 五、诊断手段沉淀

1. **服务端集成测试**：用自实现 WebSocket 客户端（手工掩码帧）连 3000/测试端口，验证 join→start→移动→射击 全链路
2. **客户端管线测试**：Node 加载真实 `app.js` + 桩 DOM/Canvas/WebSocket，逐帧验证按键→input→渲染无异常
3. **渲染数学测试**：模拟 60fps 服务端 + 60fps 客户端（含 1 tick 延迟），验证预测/平滑/收敛
4. **线上探测**：被动连接 3000 观察真实状态（phase、玩家位置、版本字段）
5. **页面调试面板**：左上角实时显示版本/连接/输入/收到/应用/玩家位置，供用户直接读数（定位后已移除）
6. **无头浏览器测试（关键）**：puppeteer-core + 系统 Chrome 无头模式，真实加载 app.js 连服务器，模拟按键，读游戏状态验证移动/射击。**复现并闭环了核心 bug**（工具在 `%TEMP%\ss_diag`）
